# Career Atlas v2

React/Vite/Tailwind and accessible Radix/shadcn-style UI components; NestJS feature modules; Postgres/Prisma; a separate durable-queue ingestion worker. Employer-authorised Greenhouse, Lever, Ashby and Workday tenants are supported. Third-party discovery boards remain excluded.

## Deployment and migration

The Docker build generates Prisma Client, runs adapter/domain tests and builds React. Startup applies committed additive migrations. The web process creates a SQLite backup on the original volume and imports user profile, application notes, statuses, contacts, preparation and existing sessions transactionally. The original SQLite file is retained. A MigrationRecord prevents repeat imports. Migration counts are logged; never remove the existing volume until exports and retention requirements are met.

Set DATABASE_URL to the Railway Postgres private reference. Preserve TRACKER_PASSWORD and APIFY_TOKEN. Web: node backend/start.mjs. Worker: the same image with ROLE=worker and no health check. Start the worker only after the web migration reports DATABASE_READY. Staging with BUILD_ONLY=1 applies the schema and runs synthetic database and HTTP endpoint checks (fixtures removed) without loading private workspace records.

## Ingestion

The PostgreSQL SourceRun table is the durable per-source queue. Claims use FOR UPDATE SKIP LOCKED with leases; transient errors retry with backoff. Every approved source is queued daily around 08:00 Asia/Kolkata with staggered starts. Checks that fail remain visible. Native public ATS APIs are preferred. HTML parsing uses structured JobPosting data; Apify is a bounded fallback. Daily Apify reservation budget defaults to $0.50 total and $0.25 per run; native API checks continue after the budget is exhausted. Full-permission approval may still be required for Apify's official Actor.

Completed source scans reconcile missing roles only after repeated complete observations. Failed, truncated and bounded HTML scans do not mark missing jobs closed. Publication, republication, modification, discovery and verification times remain separate. Ashby publishedAt is treated as last publication; Lever without original dates remains unknown. Data enrichment never writes private Application fields.

Sources are seeded from sources.v2.json and supplemented by verified registry changes. All 403 target companies are present; a company without an approved source is visibly unconfigured, not successfully scanned. Ownership requires employer evidence and an exact ATS tenant/path. Government notices from ISRO, NIELIT, BEL, BHEL, ECIL and C-DAC remain a separate manual eligibility-review queue. The worker also refreshes the public docs/jobs.json research feed; only approved URLs verified within 48 hours are admitted, using the original verification timestamp. Roles without a successful check for 48 hours are marked stale.

## User features

Server-paginated job feed, filters, saved searches, in-app alerts, explainable matching and skill gaps; job details with evidence and changes; paginated Kanban/list tracking with optimistic concurrency, history, interviews, follow-ups and resume versions; company shortlist and referrals; preparation tasks; profile; CSV/JSON export and additive import; source health and run history; official government notices and deadline review. No email is sent automatically. In-app alerts are generated by saved searches.

## Architecture

backend/domain.mjs: source policy, normalization, score/filter logic.
backend/adapters.mjs: public ATS and HTML adapters with outbound URL checks.
backend/repository.mjs: Prisma, seed and retained-volume migration.
backend/api.mjs: Nest Auth, Jobs, Applications, Profiles, Companies, Sources, Government and Dashboard modules.
backend/ingestion.mjs: queue, leases, upserts, rechecks, alerts and Apify.
backend/worker.mjs: separate scheduled worker process.
web/src/features: job feed/detail, workspace screens and referrals.
prisma/schema.prisma and prisma/migrations: tracked relational schema.

## Scope limits

Adding a company name does not establish an official source. The initial registry is intentionally bounded and must expand through verified sources. Browser-only Workday/custom sites can still fail or need site-specific adapters. Government PDF contents, automatic eligibility decisions, email notifications and a public registration flow are not implemented. The app remains one private owner workspace shared across signed-in devices.
